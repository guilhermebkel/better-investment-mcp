# FNET: Spike on FII monthly reports, access viability, and architectural options

Date: 2026-11-08. Status: PASS (spike verified; adapter implementation pending owner decision on terms).

Issue #12 asks whether monthly reports for Real Estate Investment Funds (FIIs) can be listed and downloaded from B3 FNET infrastructure by an automated client without login or captcha, whether the downloaded PDFs produce usable text with `DocumentTextService`, and what architectural design choices exist for fund identification, provider dispatching, and chunk paging.

## Technical Spike Results

A spike was executed against 5 distinct Brazilian Real Estate Investment Funds (FIIs):
- HGLG11 (Pátria Log) - CNPJ 11.728.688/0001-47 (manually supplied)
- KNRI11 (Kinea Renda Imobiliária) - CNPJ 12.005.956/0001-65 (manually supplied)
- MXRF11 (Maxi Renda) - CNPJ 97.521.225/0001-25 (manually supplied)
- XPLG11 (XP Log) - CNPJ 26.502.794/0001-85 (manually supplied)
- VISC11 (Vinci Shopping Centers) - CNPJ 17.554.274/0001-25 (manually supplied)

### 1. HTTP Access Verification
- **Listing**: GET requests to `https://fnet.bmfbovespa.com.br/fnet/publico/pesquisarGerenciadorDocumentosDados?d=1&s=0&l=30&tipoFundo=1&cnpjFundo={cnpj}&o[0][dataEntrega]=desc` returned HTTP 200 with JSON document records without login, cookies, or captcha challenges.
- **Downloading**: GET requests to `https://fnet.bmfbovespa.com.br/fnet/publico/exibirDocumento?id={id}&cvm=true` and `downloadDocumento?id={id}` returned HTTP 200 with `application/pdf; charset=UTF-8` and complete PDF byte streams.
- **Method observation**: HEAD requests to `exibirDocumento` returned `HTTP 520` (HTML response); GET requests returned `HTTP 200` with the complete PDF stream. The root cause of the HEAD 520 response was not investigated. An adapter must execute GET requests.
- **Header sets**: All three header sets (default Node.js `fetch()`, `PostmanRuntime/7.44.1`, and Chrome-like User-Agent) returned identical HTTP 200 responses and byte counts on GET:

### 2. Table and Text Usability Audit

To verify that extracted text is usable and financial figures remain intact and associable, a specific page containing financial tables was selected from each PDF. The text extracted by `DocumentTextService.extractPdf` (`unpdf`) was compared against an independent reference extraction using `pdftotext -layout`:

- **HGLG11 (Page 5, "Comentários da Gestão e Indicadores Financeiros")**:
  - Sample labels and values:
    1. `Patrimônio Líquido*`: `R$ 7,5 bilhões`

    4. `Cota de Mercado*`: `R$ 147,95`

- **KNRI11 (Page 1, "Quadro Resumo de Indicadores")**:

  - Extraction quality: In `unpdf` stream, values precede labels due to drawing stream order (`R$ 4.602.278.866,50 PATRIMÔNIO LÍQUIDO1`). Full numbers and labels are extracted with no corrupted digits.

## Terms of Service and Robots Analysis

- **`https://fnet.bmfbovespa.com.br/robots.txt`**: Returned `HTTP 404 Not Found`. An HTTP 404 on `robots.txt` does not constitute a license or affirmative grant of access.
- **`https://www.b3.com.br/robots.txt`**: Returned `HTTP 200 OK` with content `User-agent: *` and no `Disallow:` directives.
- **Portal terms**: The public consultation interface `https://fnet.bmfbovespa.com.br/fnet/publico/abrirGerenciadorDocumentosCVM` contains no terms-of-use link or explicit restrictions for automated reading.
- **Status**: The legal status of automated access to FNET is not affirmatively established by the presence or absence of robots files. Adapter implementation remains pending owner decision.

## Architectural Investigations

### 1. Provenance of Fund CNPJ (`assets.legal_id`)
In the FNET search response, the `cnpjFundo` property is returned as `null`. The search requires passing `cnpjFundo={cnpj}` as a query parameter. In this spike, CNPJs were supplied manually.
In the current repository, `assets.legal_id` is null for Brazilian assets from Yahoo Finance (`docs/product/data-map.md`, lines 57 and 75). Without a ticker-to-CNPJ source, a load of FII filings would fail with a missing-CNPJ error.

Potential options (unverified in this spike; none downloaded):
- Ingesting CVM fund cadastral open data (`cad_fi.csv` on `dados.cvm.gov.br`).
- Ingesting B3 daily instruments file (`InstrumentsConsolidatedFile.csv`).
- Seeding a static DuckDB lookup table mapping tickers to CNPJs.
- Requiring the caller or agent to provide the CNPJ.

### 2. Provider Dispatching (`BR:cvm` vs `BR:fnet`)
Currently, `INVESTMENT_MCP_FILINGS_PROVIDER=BR:cvm` routes all Brazilian filings to CVM. CVM IPE covers corporate issuers (`stock`), whereas FNET covers investment funds (`fii`).
Architectural options for dispatching:
- **Dual-key resolution in `ProviderRegistryService`**: Check `(market, assetType)` in the registry before falling back to `(market)`.
- **Composite environment variable syntax**: Extend syntax to allow `BR[fii]:fnet,BR:cvm`.
- **Composite dispatcher adapter**: Route internally within a Brazilian filing adapter.

### 3. Page Chunking
In `DocumentTextService.extractPdf`, each PDF page is mapped to an `ExtractedSegment` with its 1-based page index. `ChunkService.split` preserves exact page numbers without crossing page boundaries. The spike confirmed that all extracted chunks retain their source page number.

## Summary

The technical criteria of the spike (automated retrieval and usable text on >=4/5 documents) passed on all 5 funds. Implementation of an adapter is deferred pending the owner's decision regarding automated access terms and the source for ticker-to-CNPJ resolution.
