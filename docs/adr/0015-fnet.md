# FNET: Spike on FII monthly reports, access viability, and architectural options

Date: 2026-11-08. Status: PASS (spike verified; adapter implementation pending owner decision on terms).

Issue #12 asks whether monthly reports for Real Estate Investment Funds (FIIs) can be reliably listed and downloaded from official B3 FNET infrastructure by an automated client without login or captcha, whether the downloaded PDFs yield usable text with `DocumentTextService`, and what architectural design choices exist for fund identification, provider dispatching, and chunk paging.

## Spike results: PASS

A spike was executed against 5 distinct Brazilian Real Estate Investment Funds (FIIs) across different asset categories (logistics, hybrid/office, credit/CRI, shopping centers):
- HGLG11 (Pátria Log) - CNPJ 11.728.688/0001-47
- KNRI11 (Kinea Renda Imobiliária) - CNPJ 12.005.956/0001-65
- MXRF11 (Maxi Renda) - CNPJ 97.521.225/0001-25
- XPLG11 (XP Log) - CNPJ 26.502.794/0001-85
- VISC11 (Vinci Shopping Centers) - CNPJ 17.554.274/0001-25

### Verification criteria outcome
1. **Automated listing**: PASS. Official FNET endpoint `https://fnet.bmfbovespa.com.br/fnet/publico/pesquisarGerenciadorDocumentosDados` returned valid JSON document listings for all 5 funds using HTTP GET with no login, no cookies, and no captcha.
2. **Automated downloading**: PASS. All 5 documents were downloaded via HTTP GET from `https://fnet.bmfbovespa.com.br/fnet/publico/exibirDocumento?id={id}&cvm=true` and `downloadDocumento?id={id}` without authentication or challenge.
3. **Text usability**: PASS (5/5, exceeding the 4/5 requirement). All 5 PDFs were parsed using the repository's real `DocumentTextService.extract()`. All produced readable text with 0 empty pages (`pagesWithoutText: 0`), preserving financial numbers, tables, portfolio metrics, and distribution percentages.
4. **Header variations**: Tested across three configurations: (a) default Node.js `fetch()`, (b) `PostmanRuntime/7.44.1`, and (c) Chrome User-Agent with Portuguese `Accept-Language` and FNET `Referer`. All three header sets succeeded with HTTP 200 on GET requests.
5. **Important protocol quirk**: HTTP `HEAD` requests to `exibirDocumento` return `HTTP 520` (Cloudflare origin connection dropped by the upstream Tomcat servlet when no response body is read). All HTTP `GET` requests succeed with `HTTP 200 OK` and complete byte streams. Adapters must use `GET`, not `HEAD`.

## StatusInvest vs Official FNET evaluation

The issue noted a suggestion to use StatusInvest endpoints (`/home/mainsearchquery` -> `/fii/getassetreports documentCategory=6`). This was tested during the spike:
- `https://statusinvest.com.br/home/mainsearchquery?q=HGLG11` returns `HTTP 403 Forbidden` with a Cloudflare bot challenge under default HTTP headers. It requires forging a non-browser user agent (`PostmanRuntime/7.44.1`) to obtain JSON.
- `https://statusinvest.com.br/fii/getassetreports?fiiId=130&documentCategory=6` returned an empty response payload `{"total":0,"initialList":[]}`.
- StatusInvest's terms and bot protections make it an unsuitable, unauthorized, and fragile intermediary.
- In contrast, B3's official FNET public portal (`fnet.bmfbovespa.com.br`) serves the primary regulatory source, does not require headers masquerading, provides complete filing histories, and serves the canonical documents.

## Terms and robots.txt analysis

- **`fnet.bmfbovespa.com.br`**: Requests to `/robots.txt` return `HTTP 404 Not Found`. The public document consultation interface (`abrirGerenciadorDocumentosCVM`) has no explicit terms-of-use link or robots ban. FNET is the statutory public repository operated by B3 under CVM regulation (CVM Resolution 175 and predecessor Instrução CVM 472) for mandatory public disclosures.
- **`b3.com.br`**: `https://www.b3.com.br/robots.txt` contains `User-agent: *` with no disallow directives.
- **`dados.cvm.gov.br`**: Open data portal operates under Open Database License (ODbL).
- **Status on automated access**: Following the repository rules (`Robots is not a license; absence of terms is not approval`), automated access to FNET is technically open and unblocked, but formal approval of the terms remains a pending owner decision before an adapter is merged into product code.

## Architectural investigations (without implementation)

### 1. Origin of `assets.legal_id` (CNPJ) for FIIs
FNET's search endpoint queries by fund CNPJ (`cnpjFundo`). A search by free-text keyword without an active session redirects to the landing page. Therefore, the provider requires the fund's CNPJ.
Today, `assets.legal_id` is null for Brazilian assets from Yahoo Finance (`docs/product/data-map.md`, line 57 and 75).

**Options for obtaining FII CNPJ:**
- **Option 1A (CVM Fund Registry Open Data)**: CVM publishes daily and monthly registration files (`cad_fi.csv` / `inf_cadastral_fi.csv` on `dados.cvm.gov.br`). These list every regulated fund's CNPJ, social denomination, and CVM code. However, mapping between CVM registration and market tickers (e.g. `HGLG11`) requires ticker-name reconciliation or trading code data from B3.
- **Option 1B (B3 Daily Instruments File)**: B3 publishes a daily public instrument file (`InstrumentsConsolidatedFile.csv`) which contains the direct mapping between trading symbol (`HGLG11`), asset classification, ISIN (`BRHGLGCTF001`), and issuer legal ID (CNPJ).
- **Option 1C (Seed / DuckDB Lookup Table)**: A static or periodic seed table in DuckDB mapping B3 FII tickers to CNPJ.
- **Option 1D (Require user/agent to specify or resolve ticker link)**: Consistent with the existing gap in CVM filings (`docs/product/data-map.md` line 75), if `assets.legal_id` is null, the load fails with a message requesting the CNPJ.

*Recommendation*: Option 1C for deterministic testing, paired with Option 1B for production maintenance.

### 2. Dispatching `BR:cvm` vs `BR:fnet` by asset type
Currently, `INVESTMENT_MCP_FILINGS_PROVIDER=BR:cvm` and `INVESTMENT_MCP_DOCUMENTS_PROVIDER=BR:cvm` map market (`BR`) to a single vendor (`cvm`). CVM IPE provides filings for listed companies (`stock`), whereas FNET provides filings and managerial reports for investment funds (`fii`).

**Options for provider dispatching:**
- **Option 2A (Composite Environment Variable Syntax)**: Allow asset-type specific mappings in the environment variable, for example: `INVESTMENT_MCP_FILINGS_PROVIDER=BR:cvm,BR[fii]:fnet` or `BR:stock:cvm,BR:fii:fnet`.
  - *Consequences*: Clean configuration, explicit user control; requires extending `ProviderRegistryService.parseSettings()` and `EnvSchema`.
- **Option 2B (ProviderRegistry Dual-Key Resolution)**: In `ProviderRegistryService.resolve(category, market, assetType)`, check for a registered provider matching `(market, assetType)` before falling back to `(market)`.
  - *Consequences*: Backward compatible; defaults to primary if asset type is omitted.
- **Option 2C (Composite / Dispatcher Adapter)**: Create a `BrFilingAdapter` and `BrDocumentAdapter` that internally dispatch to `CvmFilingAdapter` or `FnetFilingAdapter` based on `request.assetType`.
  - *Consequences*: No change to environment variable syntax (`BR:b3` or `BR:cvm`), but merges separate vendor implementations behind a composite facade.

*Recommendation*: Option 2B (Dual-key resolution in registry), preserving vendor isolation per ADR 0005.

### 3. Page handling in `chunks`
- In `src/Protocols/DocumentTextProtocol.ts`, `ExtractedSegment` holds `page: number | null` and `text: string`.
- When `DocumentTextService.extractPdf(bytes)` extracts text from FNET PDFs, `unpdf` extracts pages as an array. `DocumentTextService` maps each non-empty page to an `ExtractedSegment` with 1-based page index `page: index + 1`.
- `ChunkService.split(segments)` guarantees that chunks never span across pages (`docs/product/search.md` and `ChunkService.ts:9`): each `ChunkRow` preserves the exact `page` number of the PDF.
- The spike verified that all 5 FII PDFs have exact page tracking with zero unextracted pages.
